# День 35: подготовка релиза

Задача — подготовить проверяемый пакет выпуска из изменений Git: проверки,
AI-анализ рисков и черновик release notes. Источник задания —
`../ai-advent-challenge-9/week7/day35/README.md`. Контракт —
`openspec/specs/release-preparation/spec.md` после архивации изменения.

Команда `/release prepare --base <ref> --head HEAD [--arch <architecture>]`
использует точный диапазон base → head чистого рабочего дерева. Ревьюер получает
изменения, относящиеся исходники и доступную документацию, автор release notes —
те же источники и проверенный результат ревьюера. Это два последовательных
модельных запроса сессии. История диалога и память пользователя в них не входят.
Ссылки модели проверяет приложение; итог вычисляется по фактическим проверкам.

`blocked` означает провал обязательной проверки или блокер ревью.
`incomplete` означает неполную проверку, например недоступный SDK или ошибку AI,
при отсутствии блокеров. `ready_for_manual_release` означает готовность к ручному
выпуску только в пределах выполненных проверок. Ненастроенные тесты, отсутствие
подписи и проверки на устройстве остаются явными ограничениями.

Сборка работает в отдельном снимке. Отчёты находятся во внешнем каталоге выгрузок:
`releases/<run-id>/checks.json`, `report.md`, а после успешного этапа автора —
`release-notes.md` с пометкой черновика. `/release status` читает последний
сохранённый результат после перезапуска без нового модельного запроса.
Команда не создаёт тег, не публикует пакет и не загружает его во внешние сервисы.

Правила находятся в `domains/<id>/release.json`: метаданные, обязательность
проверок и необязательные переопределения цели и шаблона команды сборки.
Релизный сценарий выбирает основную установленную цель, исключая снимки,
передаёт SDK путь к отдельной копии исходников и запрещает автоматическую
установку зависимостей сборки. Одна команда ограничена 180 секундами;
превышение даёт unavailable с сохранением доступного частичного вывода.
Настройки прежнего `/ops` сохраняются.

Теневая сборка с передачей каталога проекта и требование рабочей области
проверены по документации портала через MCP:
[sfdk, документация 5.1.5](https://developer.auroraos.ru/doc/5.1.5/sdk/app_development/build/build_engine/sfdk).
Локальный SDK — 5.1.5.105-mb2; версия документации домена по умолчанию 5.2.1
отличается, поэтому здесь использован раздел 5.1.5.

## Повторяемая демонстрация

`scripts/day35_demo.py` создаёт две независимые копии отслеживаемых обычных файлов
WebDavClient. Исходная `.git`, симлинки, неотслеживаемые файлы и `.env` не копируются;
распознанные секреты в тексте скрываются. Подготовка использует очищенный учебный
проект: если ему недостаёт зависимостей или секретов для сборки, это ограничение
должно остаться в результате. Успех сборки не имитируется.

Каждая копия получает собственные два коммита: базовое состояние и защиту
создания папки от повторного запуска. В плохом варианте дополнительно удалено
обязательное поле `Version` RPM spec; это детерминированное основание `blocked`,
даже если AI не заметит ошибку. Хороший вариант содержит исправленные метаданные;
его ожидаемый результат — `ready_for_manual_release` либо честный `incomplete`.
Если сборка выявит настоящий дефект и результат станет `blocked`, демо завершится
ошибкой и сохранит свидетельства для разбора, вместо объявления успеха.

Создание временной истории требует явного согласия через
`--approve-demo-history`. Флаг разрешает `init/add/commit` только в новых копиях
сценария; он не разрешает Git-запись в оригинал или релизный тег ff.ai.
История, профиль, память, задачи, кэш, индексы и выгрузки перенаправляются
существующими переменными FFAI во временный каталог. До и после сверяются файлы,
статус, индекс и ссылки исходного WebDavClient. Копии и отчёты сохраняются для разбора.

Сначала можно подготовить только фикстуры, без модели и SDK:

```bash
.venv/bin/python scripts/day35_demo.py \
  --source /path/to/WebDavClient --approve-demo-history --prepare-only \
  --output videos/day35-fixtures.json
```

После согласия на временную историю и при настроенном доступе к модели:

```bash
.venv/bin/python scripts/day35_demo.py \
  --source /path/to/WebDavClient --approve-demo-history \
  --model glm-5.3-flash --output videos/day35-dry-run.json
```

Для записи настоящего TUI добавьте `--visible` и выберите новый файл результата:

```bash
.venv/bin/python scripts/day35_demo.py \
  --source /path/to/WebDavClient --approve-demo-history --visible \
  --model glm-5.3-flash --output videos/day35-visible.json
```

Модель должна входить в текущий список настроек ff.ai. `--arch` передаётся
команде подготовки; при его отсутствии используется доменное значение.
Каждый запуск требует нового имени JSON; `--workspace` принимает существующий
пустой каталог вне оригинала. Скрипт использует общий фасад команд, а в видимом
режиме — настоящий процесс TUI с живым API, без модельной заглушки. Драйвер ждёт
новый отрисованный `Релиз: <status>` и `Каталог результатов:`, затем перезапускает
приложение, читает `/release status` и проверяет нулевой расход новой сессии.

JSON содержит фактические результаты и очищенные пути. Неуспешный прогон
возвращает ненулевой код и сохраняет доступные промежуточные `checks.json`.
`--prepare-only` доказывает только воспроизводимость входов и изоляцию:
он не подтверждает AI, сборку или готовность выпуска.

## Проверенный результат

Живая запись — `videos/day35-demo-verified.mp4`: 182,27 с, 3584×2240.
Ключевые кадры на 15, 80, 140 и 170 секундах прочитаны; видны настоящий TUI,
результаты с источниками и метриками, сохранённый статус после перезапуска.
Фактический машинный результат — `videos/day35-recorded-verified-result.json`.

Плохой вариант получил blocked: отсутствует Version. Исправленный получил
incomplete: метаданные и правила прошли, но SDK отказался работать в системном
временном каталоге вне своей настроенной рабочей области. Это ограничение
показано в интерфейсе и сохранено в build.log; сборка не объявляется успешной.
Для проверки SDK внутри существующей рабочей области используйте новый пустой
`--workspace` внутри неё; состав SDK, ключи и исходный проект не меняются.

В записи выполнены четыре запроса glm-5.3-flash: 30 305 токенов, расчётная
стоимость $0,00487685. Оба повторных чтения `/release status` после перезапуска
дали ноль новых запросов. Сверка подтверждает неизменность оригинального
WebDavClient и обеих входных копий во время подготовки релиза.

Материалы сдачи — `videos/day35-README-draft.md` и
`videos/day35-release-notes.md`. Видео и релиз ещё не опубликованы;
публичные ссылки добавляются после фактической публикации.
