# ff.ai

Агент-ассистент по разработке приложений под **ОС Аврора на Qt 5.6**: отвечает на вопросы
о кодовой базе и о платформе, выполняет задачи по изменению кода и проводит их через сборку,
подпись и установку. Основной интерфейс — консольный (TUI), дополнительный — тонкий локальный
web-фронтенд; ядро агента у них общее.

**Статус: планирование.** Кода ещё нет. В репозитории — документация и спецификации:
архитектура, домен, план фаз и первое изменение OpenSpec
(`openspec/changes/add-dev-assistant-bootstrap`, фаза P0).

## Что это даёт

| Режим | Пример | Что на выходе |
|---|---|---|
| **Спросить по коду** | «где инициализируется модель списка и почему так?» | ответ с цитатами `path:L10-L40`, проверенными по выданным фрагментам |
| **Спросить по платформе** | «как в Авроре получить геопозицию?» | ответ по документации портала разработчиков со ссылкой на раздел и указанием версии |
| **Сделать** | `/task add «добавь экран настроек»` | патчи файлов, отчёт, детерминированная проверка (сборка, публичные API, `.spec`, `.desktop`) |
| **Собрать** | «собери пакет под aarch64 и поставь на устройство» | сборка цели → подпись → установка через APM → запуск, каждое действие с подтверждением |

Отличие от облачных код-ассистентов не в «умнее», а в **ограниченной поверхности**: свой MCP-сервер
с белым списком операций, инварианты домена (QtWidgets запрещён, только публичные API, неизменность
состава SDK, только подписанный пакет) и обязательные проверяемые ссылки на источник. Коммиты
ассистент не делает, IDE не заменяет.

## Область применимости

Задаётся доменом — пакетом данных, а не кодом (см. [`docs/domains.md`](docs/domains.md)).

| Уровень | Содержание | Поведение |
|---|---|---|
| Целевой репозиторий | код, `.pro`/CMake, `.spec`, QML, ресурсы, git-история | отвечает и работает |
| Платформа | ОС Аврора, Qt 5.6, публичные API, RPM, Аврора SDK, подпись, устройство/эмулятор | отвечает только по документации портала, со ссылкой и версией |
| Смежное | общий C++/Qt 5, системы сборки, отладка | отвечает с пометкой «не платформенный факт» |
| Вне области | другие платформы, веб, чужие темы | фиксированный отказ с объяснением |

Область расширяется добавлением пакета: вторая платформа или версия Qt — новый каталог
`domains/<id>/`, ядро не переписывается. Подробности — [`docs/domain-aurora-qt5.md`](docs/domain-aurora-qt5.md)
и чек-лист расширения в [`docs/domains.md`](docs/domains.md).

## Установка и запуск (план)

```bash
git clone <URL репозитория> /path/to/ff.ai && cd /path/to/ff.ai
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cd /path/to/aurora-project            # целевой репозиторий приложения под Аврору
/path/to/ff.ai/ff-ai.py               # точка входа сама перезапустится в .venv
```

| Флаг / переменная | Назначение |
|---|---|
| `--repo <путь>` | целевой репозиторий; по умолчанию — текущий каталог, обязан быть git-репозиторием |
| `--domain <id>` | активный домен; по умолчанию — автоопределение по маркерам репозитория |
| `--web [--port 8765]` | поднять тонкий web-фронтенд рядом с TUI |
| `FFAI_*` | переопределение путей состояния, модели, таймаутов (описаны в `.env.example`) |

Требования: Python 3.10+ (пакет `mcp`), терминал с Unicode; для облачных моделей — API-ключ,
для локальных — llama.cpp без ключа и без сети. Команды ассистента: `/commands`, `/domain`,
`/docs` (индекс и поиск по коду), `/tool`, `/task`, `/mcp`, `/schedule`, `/context`, `/usage`,
`/memory`, `/profile`, `/invariants`, `/settings`, `/models`, `/clear`, `/exit` — по фазам
из [`docs/roadmap.md`](docs/roadmap.md).

## Структура репозитория (план)

```
ff-ai.py            # точка входа: перезапуск в .venv, --repo, --domain, --web
core/               # агент и вся логика без терминала: сессия, домены, контекст,
                    #   память, инварианты, конвейер задачи, индекс и поиск, цитаты
ui/                 # терминальный интерфейс: tui_app, панели-редьюсеры, чтение клавиш
web/                # тонкий web-фронтенд: FastAPI + SSE + статика без сборщика
mcp_server/         # свой MCP-сервер: чтение/поиск/git/сборка/патчи/выгрузки, расписание
domains/<id>/       # пакет домена: промпты, инварианты, память, профиль, инструменты,
                    #   корпуса, проверки, сценарии
assets/             # доменно-нейтральные инструкции: форматы ответа, сжатие, факты, память
tests/{unit,e2e}/   # pytest: логика без терминала и приложение целиком в псевдотерминале
docs/               # проектная документация (этот список выше)
openspec/           # спеки и активные изменения
```

Состояние пользователя (история, память, профиль, задачи, расписание) лежит в
`/path/to/data/ff-ai` (по умолчанию `$XDG_DATA_HOME/ff-ai`), индекс кода — в
`/path/to/cache/ff-ai/path-hash` (по умолчанию `$XDG_CACHE_HOME/ff-ai`), где `path-hash` —
подкаталог с хешем пути целевого репозитория. Ни в целевой репозиторий, ни в этот ничего
не дописывается само; целевой репозиторий не получает даже записи в `.gitignore` — исключения
для служебных каталогов делаются вне версионируемых файлов.

## Разработка

Работа идёт по OpenSpec: одно изменение = одна фаза плана; сначала спецификация и сценарии,
затем тесты, затем код. Полный `pytest` прогоняется один раз в конце фазы и **до** архивации
изменения. Правила процесса, инварианты и известные грабли собраны в [`AGENTS.md`](AGENTS.md).

```bash
pytest -q                                # всё, кроме сетевых тестов
openspec validate --all --strict         # проверка спецификаций
```
