# Поиск по корпусу кода и обязательные цитаты

## Why

Корпус кода построен (P1), но в ответы он не попадает: вопрос «где инициализируется модель
списка?» модель решает по общей памяти, хотя в индексе лежит точный фрагмент
`src/models.cpp:L40-L58`. Ответ без ссылки на код в этой предметной области бесполезен: его
нельзя проверить, а по памяти модель уверенно называет несуществующие методы.

Вторая причина — цитата. Платформенный факт обязан опираться на документацию портала (P4), а факт
о коде — на файл и строки. Механизм проверки уже написан и, по его же комментарию, «одинаков для
всех корпусов»: нужен второй корпус, а не вторая проверка.

## What Changes

- `core/code_retrieval.py`: локальный поиск по индексу (векторы считаются по тексту фрагментов, без
  обращений к модели), два режима — `baseline` (первые результаты, без порога и вспомогательных
  запросов) и `enhanced` (переформулировка вопроса, пул кандидатов, оценка каждого моделью, порог,
  отбор нескольких).
- `core/reranking.py` (бывший `docs_reranking`): вторая ступень становится общей для корпусов —
  различается только инструкция из ассетов; поведение документации не меняется (инструкция по
  умолчанию та же).
- Настройки сессии: режим, порог, размеры пулов `before`/`after`; `/code retrieval`, `/code threshold`,
  `/code tune`, `/code trace` — отчёты и правки без обращений к модели.
- Гейт «не знаю»: кандидаты есть, но все ниже порога — фиксированный текст вместо ответа по памяти,
  без запроса к модели.
- Фрагменты кода идут в запрос отдельным служебным сообщением с идентификатором `path:L10-L40`, а
  ответ проверяется общей проверкой цитат (`core/citations.py`) с минимумом длины цитаты для кода.
- Комбинированный вопрос (код и платформа) доставляет фрагменты обоих корпусов, и проверка цитат
  видит их вместе.

## Impact

- Новые файлы: `core/code_retrieval.py`, `assets/code_query_prompt.md`,
  `assets/code_rerank_prompt.md`, тесты.
- Правки: `core/agent.py` (поиск перед вопросом, служебное сообщение, проверка цитат), `core/session.py`
  (команды и отчёты), `core/config.py` (лимиты и минимум цитаты), `core/domains.py` (порог и пулы
  домена при необходимости), документация.
- Расход: в режиме `enhanced` добавляются вспомогательные запросы (переформулировка и оценка
  кандидатов); в `baseline` — ни одного.
