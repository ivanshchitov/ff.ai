## Why

День 32 требует автоматического AI-ревью нового PR на реальном проекте WebDavClient. Контекст недели 7 требует объединить инструменты, RAG и модель в полезный конвейер с триггером и наблюдаемыми этапами, сокращая ручное участие.

## What Changes

- Добавить неинтерактивный запуск ff.ai для ревью между base/head коммитами.
- Передавать модели diff, список изменений и доступное содержимое изменённых файлов.
- Переиспользовать RAG по исходникам и документации проекта, показывать доставленные источники.
- Сохранять Markdown-ревью с потенциальными багами, архитектурными проблемами и рекомендациями, а также машинный отчёт этапов и расхода.
- Подготовить GitHub Actions workflow для PR в личном WebDavClient и локальное воспроизведение для записи видео.
- Публиковать успешное ревью в один обновляемый комментарий PR со ссылкой на запуск; устаревшие результаты не публиковать.
- Сделать AI review gate обязательной проверкой: баги и архитектурные проблемы блокируют merge, рекомендации без проблем не блокируют.

## Capabilities

### New Capabilities

- `pr-review-pipeline`: автоматическое ревью PR через ff.ai с RAG и отчётом выполнения.

### Modified Capabilities

Нет.

## Impact

Новый CLI и модуль ревью в ff.ai, инструкции модели в assets, workflow и пример подключения, тесты, README, AGENTS и сценарий дня 32. Повторно используются APIClient, корпус домена и локальный поиск. Workflow для WebDavClient готовится в ff.ai; установка в соседний репозиторий учитывает разрешения среды. Публикация кода, создание PR и настройка секретов — отдельные действия.
