# Задачи

## 1. Корпус и обход

- [ ] 1.1 Тесты отбора файлов: расширения домена, исключения, предел размера, двоичные файлы, `.gitignore`
- [ ] 1.2 Обход через `git ls-files` в git-репозитории и обычным обходом вне git; в отчёте виден способ
- [ ] 1.3 `/code index` не создаёт в целевом репозитории ни одного файла

## 2. Разбиение

- [ ] 2.1 `fixed`: окна строк с перекрытием, границы по строкам, последний фрагмент без хвоста
- [ ] 2.2 `structural`: начало блока по правилам домена, склейка мелких блоков, потолок размера, крупный блок режется
- [ ] 2.3 Инвариант: строки файла по диапазону фрагмента совпадают с его текстом

## 3. Хранилище

- [ ] 3.1 SQLite-схема: фрагменты (стратегия, идентификатор, путь, строки, текст, хеш) и метаданные
- [ ] 3.2 Путь в кэше состояния по хешу пути репозитория; переопределение переменной окружения
- [ ] 3.3 Атомарная замена: сбой сборки не затирает прежний индекс
- [ ] 3.4 Снимок сборки: число файлов, фрагментов, пропусков по причинам, время сборки

## 4. Команды и интерфейс

- [ ] 4.1 `/code index [fixed|structural]`, `/code status`, `/code compare` без обращений к модели
- [ ] 4.2 Отчёт кэшируется в фасаде, строки отчёта попадают в журнал и в панель команд

## 5. Сквозные проверки

- [ ] 5.1 e2e: `/code index` на временном проекте под Аврору, `/code status` с путём в кэше, репозиторий не изменён
- [ ] 5.2 e2e: `/code compare` печатает обе стратегии с диапазонами; `/usage` подтверждает ноль обращений к модели
- [ ] 5.3 e2e: сбой сборки (недоступный каталог) оставляет прежний индекс
