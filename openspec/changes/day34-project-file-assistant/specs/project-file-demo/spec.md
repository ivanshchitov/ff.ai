## Purpose

Дать пользователю повторяемый пример исследования и изменения файлов реального проекта по цели с проверяемыми источниками и diff.

## ADDED Requirements

### Requirement: Исследование файлов по цели

Демонстрационный запуск SHALL принимать цель без перечисления входных путей, использовать автоматический поиск и чтение файлов и показывать результат анализа с источниками минимум из трёх файлов.

#### Scenario: Поиск реализации и использований
- **WHEN** пользователь просит найти реализацию создания папки и использования соответствующего компонента без изменения проекта
- **THEN** ассистент сам инициирует чтение и поиск, показывает найденные связи с источниками, сохраняя файлы без изменений

### Requirement: Документ по прочитанному коду

Демонстрационный запуск SHALL создавать документ на основе прочитанных исходников через существующий поток плана, diff и подтверждения записи.

#### Scenario: Подтверждённое создание документа
- **WHEN** пользователь задаёт цель документирования поведения и подтверждает показанный diff
- **THEN** документ сохраняется в демонстрационном проекте, исходники остаются прежними, а результат содержит идентификатор операции и diff

#### Scenario: Отказ от записи
- **WHEN** пользователь отклоняет предложенный diff или не отвечает до таймаута
- **THEN** соответствующие файлы остаются без изменений и результат явно сообщает об отказе

### Requirement: Повторяемость и изоляция

Демонстрационный запуск SHALL работать с отдельной копией проекта и отдельным состоянием, сохранять доказательства результата вне исходного проекта и явно сообщать о недоступных проверках.

#### Scenario: Повторный запуск
- **WHEN** сценарий запускают повторно с тем же исходным WebDavClient
- **THEN** он получает свежую копию и состояние, выполняет три сценария, сохраняет новые артефакты и подтверждает неизменность исходного проекта

#### Scenario: Недоступный внешний ресурс
- **WHEN** модель, MCP или захват экрана недоступны
- **THEN** запуск сообщает причину и невыполненную часть, сохраняя исходный проект и не выдавая заглушку за успешную живую проверку

### Requirement: Изолированные субагенты до записи

Ассистент SHALL передавать разработчику цель и актуальные источники, а независимому ревьюеру — цель, источники и предложенный diff в отдельном контексте без истории чата и рассуждений разработчика. Детерминированные проверки SHALL предшествовать ревью. Роли, результаты и расход каждого запроса SHALL быть видны пользователю.

#### Scenario: Замечание ревьюера
- **WHEN** ревьюер отклоняет первую версию допустимого патча
- **THEN** разработчик получает замечания и одну попытку исправления, а запись возможна только после положительного ревью и подтверждения пользователя

#### Scenario: Проверка не завершена
- **WHEN** ревьюер недоступен, вернул некорректный или обрезанный ответ либо отклонил вторую версию
- **THEN** патч не применяется, причина сохраняется в результате подзадачи и пользователь видит нерешённую проблему

### Requirement: Изменение кода по цели

Демонстрация SHALL включать защиту создания папки от повторного запуска во время текущей операции с проверкой повторного запуска после успеха и ошибки и обновлением документации.

#### Scenario: Защита повторного вызова
- **WHEN** пользователь задаёт цель защиты создания папки без перечисления путей
- **THEN** ассистент сам находит код, предлагает проверенный патч и после подтверждения сохраняет изменения в копии проекта, показывая результаты проверки повторного вызова и завершения операции
