## Context

Источник задания: `../ai-advent-challenge-9/week7/day31/README.md`.
Дословные критерии минимума:

- «README + папка docs в RAG»
- «MCP — хотя бы git branch»
- «/help отвечает на вопросы о структуре проекта»

Формат: «Видео + Код». Название решения: ff.ai.
Локальный корпус уже включает Markdown, JSON и YAML. MCP `repo_git`
разрешает `status`; `status --short --branch` возвращает ветку без изменения git.
Сейчас `/help` неизвестна, а обычный ввод проходит классификатор разработки.

## Goals / Non-Goals

Цель: явный ответ о целевом проекте с документацией и свежим MCP-контекстом,
проверяемый по путям и строкам. Записать реальную демонстрацию на копии WebDavClient.
Новые инструменты, отдельный корпус, автоматическая правка WebDavClient,
сборка SDK и публикация не входят в изменение.

## Decisions

1. Общий обработчик сессии `/help [вопрос]`. Пустой аргумент означает вопрос
   о структуре проекта, README, docs и основных каталогах. Команда обходит
   классификатор и не создаёт задачу, даже если аргумент содержит просьбу изменить код.
2. Переиспользовать индекс `/rag-code`; пользователь строит его командой
   `/rag-code index`. `/help` включает поиск для своего запроса, сохраняет выбранный
   режим отбора и восстанавливает настройки после завершения, включая ошибку.
   Недоступный, отсутствующий или stale-индекс явно называется; устаревшие данные
   не доставляются. Без источников модель получает запрет выдумывать структуру.
3. Получать ветку собственным MCP-сервером, привязанным к корню проекта:
   `repo_git(args="status --short --branch")`. Для этого не нужен обход серверов
   портала. Ошибка MCP передаётся как недоступность, без подстановки локального git.
   В журнале видны инструмент и свежий результат. Detached HEAD остаётся detached.
   Имя инструмента и аргументы объявлены в `assets/project_help.json`, чтобы ядро
   не знало имён инструментов сервера. MCP-чтение запрещает необязательные записи Git
   через `GIT_OPTIONAL_LOCKS=0`. Перед `/help` корпус сравнивается с текущими файлами
   и результатом их разбиения: ручные изменения и добавления также делают его stale.
4. Добавить необязательный контекст запроса в `RepoAgent.ask`: отдельное сообщение
   с read-only инструкцией и результатом MCP. Документы и MCP-вывод считаются данными.
   Для `/help` отключить поиск портала и модельный выбор дополнительных инструментов
   на время запроса; восстановить настройки в finally.
5. `CommandResult` несёт необязательный `Answer`. TUI использует существующее
   отображение ответа, источников и метрик. Web возвращает ответ, источники и метрики
   через `/api/command` и показывает их в ленте. Расход и история используют общий путь.

Альтернативы: простая справка по командам не отвечает заданию; отдельный RAG-корпус
дублирует готовую инфраструктуру; модельный выбор git-инструмента не гарантирует
получения текущей ветки при каждом `/help`.

## Validation

TDD для общего обработчика и интерфейсов. Проверить README и docs в фактическом
запросе, MCP по stdio над временным git-проектом, отсутствие задач и записи файлов,
отсутствие индекса, отказ MCP, detached HEAD, восстановление настроек при APIError.
Полный локальный набор до архивации; OpenSpec strict до и после.

## Demo

Изолированная временная копия WebDavClient; все FFAI-пути перенаправлены.
Проверить отсутствие секретов в доставляемых документах перед живым запросом.
Показать `/rag-code index`, `/help` о структуре, `/help` о соглашениях разработки,
пути README и docs, полученную через MCP ветку, `/rag-code trace` и `/usage`.
Сначала сухой прогон и recorder doctor; затем реальная запись экрана 30–600 секунд
с проверкой ключевых кадров. При недоступности записи передать точную причину
и ручной сценарий. Черновики находятся в игнорируемом `videos/`;
URL опубликованного видео и релиза не объявляются существующими заранее.
