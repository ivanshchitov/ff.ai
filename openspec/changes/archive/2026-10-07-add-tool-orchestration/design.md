# Решения фазы P5

## Раунды расширяют цепочку, а не заменяют её

Один запрос выбора с цепочкой шагов решает большинство задач и стоит один вспомогательный запрос.
Отдельный раунд нужен там, где аргументы следующего шага зависят от **содержимого** предыдущего
результата: «найди в коде класс окна → найди в документации портала упомянутый там API». Раунд —
это тот же запрос выбора плюс выполненные шаги, поэтому модель видит, что уже сделано, и не
повторяет это. Флоу в один раунд завершается сам: продолжение требует явной пометки, иначе
автовызов стоил бы двух запросов на каждый вопрос.

## Данные передаются по ссылке, а не пересказом

Аргумент, значение которого целиком равно `$N`, заменяется полным текстом результата шага N,
включая ссылку на отдельную строку многострочного значения (модель собирает выгрузку из
нескольких результатов). Пересказ моделью недопустим: он теряет символы и не проверяется. Поэтому
`$N` внутри строки вместе с другим текстом остаётся как есть — иначе «цена $5» дала бы подстановку
из чужого шага. Шаги нумеруются глобально по всем раундам, чтобы ссылка не зависела от раунда.

## Маршрут шага — код, а не слово модели

Сервер определяется по снимкам подключений: названный — если он объявил инструмент; иначе
единственный объявивший (с пометкой перенаправления в отчёте). Отказ при отсутствии и при
неоднозначности — это шаг без вызова, а не догадка; процесс сервера при этом не запускается.
Имена инструментов в `core/` и `ui/` не появляются: их приносят серверы, каталог строится из
снимков.

## Результат — служебное сообщение, а не история

Результаты инструментов входят в запрос ответа отдельным служебным сообщением выше реплик
диалога: это данные для текущего вопроса, а не часть разговора. В историю и память они не
попадают — при следующем запуске такой контекст был бы ложным. Без вызова форма запроса не
меняется.

## Бюджеты — из живого прогона, а не из соображений

Цена такого решения видна по опыту: 33 000 символов руководства в каждом раунде съедали бюджет
рассуждения, а сырой документ в запросе ответа приводил к пустому ответу на исчерпанном
`max_tokens`. Отсюда три разных бюджета: результаты последнего раунда целиком, ранние — коротко,
каждый шаг в запросе ответа — с ограничением. Все сокращения помечаются, чтобы модель знала, что
видит часть текста.

## Обрыв шага — причина, а не данные

Ошибка инструмента останавливает цепочку: продолжать её на неверных данных опаснее, чем
остановиться. Текст ошибки не становится материалом ответа (это служебная информация), но его
видит пользователь строкой журнала. Вопрос отправляется с результатами выполненных шагов.

## Сессия на флоу, а не вызов на шаг

Поднимать сервер на каждый вызов дорого: флоу открывает по соединению на
сервер и держит его до конца вопроса — запуск stdio-процесса это стоимость, которая на трёх шагах
оплачивается трижды. Соединения закрываются вместе с флоу, наружу уходят только снимки.

## Автовызов включён по умолчанию, но выключен в тестах

Один вспомогательный запрос на вопрос — цена автовызова. Пользователь платит её по умолчанию
(иначе «ассистент» отвечает без обращения к коду и документации), а тесты, считающие запросы,
получают выключенный автовызов переменной окружения — иначе они мерили бы запрос выбора вместо
ответа.
