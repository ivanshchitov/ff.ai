# Предложение: документация портала как корпус ответа с проверяемыми ссылками

## Why

Промпт домена уже требует подкреплять платформенные факты документацией портала, а живой прогон
показал, чем это кончается без источника: на вопрос «как в Авроре получить координаты устройства»
ассистент ответил «платформенных фактов без документации портала дать не могу» — честно, но
бесполезно. В P3 сервер документации подключён, и инструменты работают: поиск отдаёт пути и
сниппеты, `get_document` — полный текст, `get_doc_versions` — список версий.

Не хватает последнего звена: приложение должно само приносить нужные фрагменты в запрос и
проверять, что ответ на них ссылается. Тогда платформенный ответ появляется, а выдуманный путь
документа или имя API — нет.

## What Changes

- **Поиск по документации перед вопросом.** При включённом режиме приложение ищет по документации
  портала тем же вопросом пользователя, отбирает лучшие попадания, догружает полный текст верхних
  документов и вырезает из него фрагмент вокруг найденного места. Никаких локальных копий:
  корпус живёт на портале, а свежесть обеспечена тем, что его читают в момент вопроса.
- **Версия документации — часть ответа.** Приложение берёт список версий, выбирает актуальную
  (или заданную пользователем), передаёт её в поиск и указывает в контексте; рассинхрон
  с установленным SDK проговаривается.
- **Фрагменты уходят модели отдельным системным сообщением** с заголовками (путь документа,
  раздел, версия), с ограничением числа фрагментов и объёма каждого, с пометкой об обрезке.
- **Ответ обязан ссылаться на доставленное.** Проверка кодом: ответ называет путь или
  идентификатор доставленного фрагмента **и** приводит дословную цитату из его текста; иначе —
  один повтор, затем замена фиксированным текстом. В диалог и историю попадает только то, что
  увидел пользователь. Проверка общая по механизму: тот же модуль будет проверять ссылки на код
  в P2 — отличается только вид идентификатора (`doc/...` против `path:L10-L40`).
- **Режим и отчёт.** `/docs mode on|off` — выключенный режим не делает ни одного сетевого вызова
  и не добавляет ни одного сообщения; `/docs version <версия>`; `/docs trace` — что искали, где,
  в какой версии, что доставили, чем закончилось. Строка `Источники:` после ответа печатает
  доставленные фрагменты. Отчёты не обращаются к модели.
- **Доступность и отсутствие результатов — тоже состояния.** Недоступный сервер даёт строку
  «документация портала недоступна: причина» и инструкцию в запросе, а не молчание и не выдумку;
  пустой поиск даёт инструкцию не утверждать платформенные факты без источника. Жёсткого гейта
  «отвечаю только тогда, когда нашёл» в P4 нет: пока у ассистента это единственный корпус,
  такой гейт сломал бы смежные вопросы (уровень 3 области), которые и так отвечаются честно.
- **Локальная индексация документации не делается.** Портал отдаёт свежий текст по запросу;
  копия у нас устареет и разойдётся с версиями.

## Capabilities

### New Capabilities

- `docs-retrieval`: поиск по документации портала, выбор версии и раздела, доставка фрагментов
  в запрос, состояния доступности и отчёт о том, что именно доставлено.
- `answer-citations`: обязательные проверяемые ссылки в ответе — идентификатор доставленного
  фрагмента и дословная цитата из него, повтор и замена при нарушении.

### Modified Capabilities

Нет. `mcp-integration` (P3) дал инструменты, `question-answering` (P0) задал границы области и
распределение инструкций по сообщениям — эта фаза их использует, не меняя. Требование о ссылке
на документацию у платформенного факта уже есть в `domain-profiles`; здесь появляется механизм,
который его выполняет.

## Impact

- Код: `core/docs_retrieval.py` (поиск, версия, фрагменты, снимок), `core/citations.py`
  (проверка ссылок и цитат, повтор, замена), `core/agent.py` (шаг поиска перед вопросом,
  контекст и инструкция в запросе, проверка после ответа, снимки), `core/session.py` и
  `ui/tui_app.py` (команда `/docs`, строка `Источники:`, журнальные строки), `core/config.py`
  (границы фрагментов и минимум цитаты).
- Ассеты: `assets/docs_citations_prompt.md` (как ссылаться на доставленные фрагменты).
- Данные домена: `domains/aurora-qt5/servers.json` — разделы поиска по умолчанию и слова-признаки
  вопросов о версиях (данные, а не код).
- Тесты: `tests/unit/test_docs_retrieval.py`, `tests/unit/test_citations.py` (новые),
  `tests/fake_docs_server.py` (заглушка сервера документации по stdio со своим маленьким
  корпусом), дополнения в `test_agent.py`, `test_session.py`,
  `test_tui_app.py`, сквозной `tests/e2e/test_docs_flow.py`, сетевой `test_docs_network.py`.
- Документация: `README.md`, `AGENTS.md`, `docs/roadmap.md`, `docs/domain-aurora-qt5.md`
  (что механизм делает, а что остаётся за промптом).

## Критерии приёмки

- Вопрос о платформе получает ответ со ссылкой на путь документа и дословной цитатой из
  доставленного фрагмента; ответ без ссылки заменяется текстом «не знаю» с просьбой уточнить.
- Вопрос о версии («в какой версии появилось…») отвечается по примечаниям к выпуску, а версия
  документации названа в ответе.
- Недоступный сервер документации не мешает ответу: строка о недоступности, инструкция в запросе,
  сессия продолжается.
- `/docs mode off` не делает ни одного сетевого вызова и не добавляет сообщений; отчёты не
  обращаются к модели.
- Обычный прогон тестов не ходит в сеть; реальный сервер проверяется отдельным `network`-тестом.
- Живая демонстрация: два-три платформенных вопроса, один из них — про версию, и один ответ
  с вырезанным фрагментом документа.
