## Context

См. `proposal.md` — Why. Что уже есть: `core/mcp_client.py` (два транспорта, список инструментов,
вызов), `core/mcp_registry.py` (реестр, сервер документации объявлен пакетом домена),
`core/agent.py` (лог, стратегии контекста, память стратегии, расход), `core/session.py` (фасад,
команды, снимки), промпт домена с правилами работы с документацией. Пакет домена объявляет один
внешний сервер: `aurora-docs`, `http`, `https://developer.auroraos.ru/api/mcp`, проверка вызовом
`echo`.

Что показал живой вызов сервера портала (P3): `search` отдаёт `path`, `title`, `index`, `url` и
1–2 сниппета по ~300 символов; `get_document` отдаёт полный текст документа; `get_doc_versions` —
список версий, где актуальная помечена `latest: 1` (она не самая старшая из списка).

## Goals / Non-Goals

**Goals:**

- Платформенный ответ приходит с проверяемой ссылкой на путь документа и дословной цитатой.
- Ответ без ссылки до пользователя не доходит: повтор, затем честное «не знаю».
- Режим, версия и отчёт управляются командами; выключенный режим не делает сетевых вызовов.
- Ни одного лишнего запроса к модели на сам поиск: корпус читается инструментами MCP.

**Non-Goals:**

- Локальная индексация документации (копия устареет и разойдётся с версиями портала).
- Переписывание запроса и реранкинг моделью: в P4 поиск идёт исходным вопросом. Если качество
  отбора окажется недостаточным, это отдельное измерение: у поиска есть две ступени отбора
  (реранкинг появляется отдельной фазой P4.5).
- Жёсткий гейт «отвечаю только по найденному»: пока документация — единственный корпус, гейт
  ломал бы смежные вопросы уровня 3, которые сейчас отвечаются честно и полезно.
- Поиск по коду целевого репозитория и цитаты `path:L10-L40` — фаза P2 (общий модуль проверки
  ссылок появится здесь и будет переиспользован там).

## Decisions

**Поиск делает приложение, а не модель.** Инструменты MCP у модели появятся как автовызов только
в P5; в P4 приложение само ищет по вопросу и приносит фрагменты. Альтернатива — ждать P5 — 
оставила бы фазу без результата, а её ценность как раз в том, что платформенные ответы появляются
сразу.

**Запрос — исходный вопрос, без переписывания.** Портал сам ранжирует результаты и отдаёт свои
сниппеты; модель-переписыватель добавила бы по запросу к каждой реплике, а выигрыш неочевиден.
Решение обратимо: `docs_retrieval` — одно место, где строится запрос.

**Разделы поиска — данные пакета.** Запись сервера объявляет раздел по умолчанию (`docs`) и
слова-признаки вопросов о версиях (`версия`, `появил`, `выпуск`), по которым добавляется раздел
примечаний к выпуску. Список разделов не зашивается в код: их состав — знание домена.

**Версия выбирается один раз и называется в ответе.** `get_doc_versions` вызывается при первом
поиске и кэшируется на сессию; пользователь может задать версию командой. Версия попадает
в заголовок фрагментов и в строку источников: без неё платформенный факт нельзя проверить.

**Фрагмент строится из сниппетов и вырезанного текста документа.** `search` даёт короткие
сниппеты (их хватает для оценки), `get_document` — полный текст: приложение находит в нём место
первого совпадения слов вопроса и вырезает окно фиксированного размера с пометкой об обрезке.
Идентификатор фрагмента — путь документа: именно его и должна назвать модель.

**Проверка ссылок — общий модуль `core/citations.py`.** Он ничего не знает ни о документации,
ни о коде: на вход `DeliveredFragment(identifier, source, title, text)`. Образец
проверки (дословная цитата после нормализации, только из доставленного, один повтор, замена)
берётся сюда целиком, потому что он уже проверен в бою.

**Состояния поиска — данные снимка.** `disabled`, `ok`, `no_candidates`, `unavailable`; отчёт
`/docs trace` печатает их и то, что доставлено. Интерфейс не читает внутренности агента.

## Risks / Trade-offs

- [Сниппеты по 300 символов могут не содержать нужного факта] → верхние документы догружаются
  целиком и из них вырезается окно вокруг совпадения; если и этого мало, ответ опирается на то,
  что есть, и цитата всё равно проверяется.
- [Полный документ может быть очень большим] → фрагмент всегда обрезается до предела, пометка
  об обрезке остаётся в тексте; бюджет запроса в любом случае ограничен потолком сессии.
- [Лишние токены в каждом запросе] → у пользователя есть `/docs mode off`; фрагменты ограничены
  по числу и объёму, а сам поиск токенов не тратит.
- [Проверка цитат отвергает перефразированный ответ] → намеренно: перефраз — не
  цитата, а требование призвано ловить выдуманные пути и имена API.
- [Портал недоступен (сеть, блокировка)] → состояние `unavailable`, строка о недоступности,
  инструкция в запросе, сессия продолжается; сетевой тест отделён маркером.
- [Версия документации новее установленного SDK] → правило уже в промпте домена; приложение
  добавляет фактические номера в контекст фрагментов, чтобы ответ называл рассинхрон.

## Migration Plan

Состояние на диске не меняется: кэш версий живёт в памяти сессии. Пакет домена дополняется
полями записи сервера (раздел и слова-признаки) — они необязательны, старый пакет грузится как
прежде. Откат — снятие шага поиска из `agent.ask`.

## Open Questions
