# Планировщик здоровья репозитория

## Why

Проверки репозитория — сборка цели, актуальность индекса, поиск модулей вне публичного API — нужны
регулярно, а не только когда пользователь о них вспомнит. Ассистент уже умеет всё это делать
инструментами; не хватает расписания и исполнителя, который работает без открытого терминала.

## What Changes

- `core/schedule_store.py`: задания (`tool`, аргументы, период, следующий запуск), журнал прогонов с
  пределом и накопленное между прогонами; терпимое чтение.
- `mcp_server/scheduler.py`: инструменты планировщика в собственном сервере репозитория и три
  задания домена — сборка цели (через белый список команд), обновление индекса кода, поиск идиом
  Qt 6 и модулей вне публичного API; исполнитель и часы внедряются.
- `ff-ai-scheduler.py`: фоновый исполнитель (`--once`, `--interval`, `--command`), работающий как
  обычный клиент MCP.
- Агент объявляет о прогонах, которых пользователь ещё не видел, и не выдаёт историю за новость;
  `/schedule` печатает снимок.

## Impact

- Новые файлы: `core/schedule_store.py`, `mcp_server/scheduler.py`, `ff-ai-scheduler.py`, тесты.
- Правки: `mcp_server/repo_server.py` (регистрация инструментов), `core/agent.py` (снимок и
  объявление), `core/session.py` (`/schedule`), `ui/tui_app.py` (строка старта и объявление).
- Расписание пишет только серверный процесс, приложение только читает: гонки нет по построению.
