# Решения фазы P9

## Расписание пишет один процесс

Файл расписания пишет только серверный процесс (внутри вызова «выполнить просроченное»), приложение
только читает и перечитывает. Это снимает гонку по построению: два процесса не пишут один файл, а
приложению не нужны ни блокировки, ни свой планировщик.

## Задания — собственные инструменты сервера

Задание вызывает инструмент того же сервера репозитория, а не второй сервер: у второго появился бы
клиент MCP внутри сервера MCP. Инструменты планировщика в свой список заданий не попадают — иначе
задание «выполнить просроченное» замкнуло бы исполнителя.

## Курсор — пара «время и число прогонов»

Один проход записывает все просроченные задания с одним и тем же временем, поэтому курсор из одного
времени проглотил бы соседей по проходу. Курсор — пара (время, сколько прогонов на нём), и он
перенесён в хранилище: привязка к агенту делала бы его непроверяемым и теряла бы при перезапуске.

## Накопленное не обрезается

Журнал прогонов ограничен, а накопленное — нет: «увиденное впервые» считается по нему, и обрезка
превратила бы повтор в новость.
