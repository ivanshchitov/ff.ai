# Решения фазы P7

## Инструмент берётся из окружения, а не из кода

Путь к `sfdk` — свойство машины разработчика, а не приложения: он приходит переменной окружения
(`FFAI_SFDK`) с разумным значением по умолчанию. Те же правила, что для прочих внешних путей:
в `.env.example` появляется переменная, а отсутствие инструмента — называемая причина, а не
исключение из глубины.

## Цели спрашиваются у инструмента

Список целей — данные SDK и меняется с его обновлением; свой список в коде устареет молча. Поэтому
цели читаются из вывода инструмента, а правила домена задают только образец (что считать целью) и
предпочитаемую архитектуру. Так же устроены инструменты репозитория: имена приносит источник.

## Команды — данные домена, запуск — без оболочки

Команды шагов (сборка, подпись, проверка, установка, запуск) и запрещённые команды объявляет пакет
домена: у другой платформы другой SDK. Запуск — списком аргументов, без оболочки и с белым списком,
как у инструментов репозитория: строка, склеенная из частей, — это приглашение к инъекции, а
maintenance-команда должна отсекаться *до* процесса.

## Сборка в отдельный каталог

`qmake` и `make` в корне проекта оставляют `Makefile`, `.qmake.stash` и каталог приложения — это
наблюдалось на живом прогоне P6. Сборка в `build_<arch>/` возвращает рабочему дереву чистоту, а
собранный пакет ищется в известном каталоге, а не «где-то в проекте».

## Подпись: фраза из окружения, проверка по строкам

Интерактивный ввод кодовой фразы в конвейере невозможен: он ломает и автоматизацию, и демонстрацию.
Фраза приходит переменной окружения; если её нет — шаг не выполняется с названной причиной.
Проверка подписи решается по строкам вывода проверяющей команды, а не по коду возврата: `rpm`
успешно отвечает и на пакет без подписи, и код возврата в этом случае ничего не говорит.

## Необратимые шаги подтверждаются, и подтверждение даёт интерфейс

Подпись, установка и запуск меняют чужую систему: без подтверждения они не выполняются, и
отсутствие подтверждения — названная причина, а не молчаливый пропуск. Доступность подтверждения
даёт интерфейс (как у патчей задачи): библиотечное использование конвейера по умолчанию ничего
необратимого не делает.

## Состояние рядом с проектом, но не в файлах проекта

Выбор цели — свойство проекта, поэтому состояние лежит в `<repo>/.aurora/`, но путь добавляется в
`.git/info/exclude`: локальный список исключений git — не отслеживаемый файл, и правка репозитория
не требуется. Тот же приём описан в рисках плана: состояние инструмента не должно менять
`.gitignore` чужого проекта.
