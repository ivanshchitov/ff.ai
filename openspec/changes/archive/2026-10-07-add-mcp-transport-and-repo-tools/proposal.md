# Предложение: MCP-транспорты, реестр и инструменты репозитория

## Why

Ассистент P0 отвечает только тем, что знает модель, и сам это признаёт: промпт домена требует
подкреплять платформенные факты документацией портала, а читать её нечем — на живой прогон
вопрос «как в Авроре получить координаты устройства» он ответил честным отказом со ссылкой на
отсутствие поиска. Так же он отказывается править файлы: содержимое репозитория ему недоступно.

Нужен слой, который даёт ассистенту данные: подключение к MCP-серверам — серверу документации
портала (remote, без токена) и собственному серверу репозитория. Без него следующие фазы (поиск
по коду, документация как корпус ответа, конвейер задачи) упрутся в ту же стену.

## What Changes

- **Транспорты как данные.** Запись реестра объявляет сервер: имя, транспорт (`stdio` или `http`),
  команду запуска либо адрес, описание, ключи окружения для секретов и — необязательно — имя
  инструмента проверки соединения. Имён инструментов конкретных серверов в `core/` и `ui/`
  по-прежнему нет.
- **Remote-транспорт.** Клиент учится подключаться к серверу по адресу (streamable HTTP) рядом
  со stdio: у пакета `mcp` 2.3 это `Client(url)` с тем же жизненным циклом «поднять — спросить —
  закрыть», что и у stdio-режима. В реестр добавляется сервер документации портала
  (`dev-aurora`, `https://developer.auroraos.ru/api/mcp`, токен не нужен).
- **Реестр собирается из домена и из кода.** Серверы, относящиеся к области применимости, домен
  объявляет в пакете (`domains/aurora-qt5/servers.json`); собственный сервер репозитория —
  часть инструмента и объявляется в ядре. Оба попадают в один реестр, замена сервера остаётся
  правкой данных.
- **Собственный сервер репозитория** (`mcp_server/`): перечень файлов, чтение файла с номерами
  строк, поиск по тексту, git только на чтение, запуск разрешённых команд сборки и сохранение
  выгрузки. Инструментов **записи в целевой репозиторий** в этой фазе нет: изменение кода
  появится вместе с конвейером задачи, где есть подтверждение и проверка (P6). Белые списки
  команд и git-подкоманд приходят из пакета домена (`tools.json`).
- **Видимость:** `/mcp` (снимок по каждому серверу: имя, версия, протокол, инструменты, ошибка),
  `/mcp refresh`, `/tool` (перечень инструментов с параметрами), `/tool call <инструмент>
  ключ=значение`. Стартовая сводка строкой до заголовка: «MCP: N/M серверов, K инструментов».
- **Отложено в P5** (сознательно): автовызов инструмента моделью, цепочки и раунды
  (`/tool auto`, `mcp_tools`). В P3 вызов только ручной — сначала надо убедиться, что соединение
  и вызов работают.

## Capabilities

### New Capabilities

- `mcp-integration`: реестр серверов как данные, транспорты stdio и remote, разовое подключение,
  список инструментов и вызов, проверка соединения, снимок отчёта для интерфейса и ручной вызов.
- `repo-tools`: собственный MCP-сервер проекта над целевым репозиторием — чтение, поиск, git
  на чтение, разрешённые команды сборки, выгрузка результатов, с жёсткими границами путей и команд.

### Modified Capabilities

Нет. `domain-profiles` (P0) уже требует, чтобы домен объявлял свои корпуса и белые списки команд
и подключался тем же реестром; эта фаза это требование выполняет, а не меняет. `agent` и
`terminal-ui` расширяются командами и снимками — их требования описаны в новых возможностях.

## Impact

- Код: `core/mcp_client.py` (транспорты и вызов), `core/mcp_registry.py` (реестр и снимки),
  `core/domains.py` (необязательные разделы пакета `servers` и `tools`), `core/config.py`
  (переопределения окружением для тестов), `core/session.py` (обход реестра, снимок, вызов),
  `ui/tui_app.py` и `ui/commands_screen.py` (команды `/mcp`, `/tool`).
- Новое: `mcp_server/repo_tools.py`, `mcp_server/repo_server.py` (отдельный процесс по stdio).
- Данные домена: `domains/aurora-qt5/servers.json` (сервер документации портала),
  `domains/aurora-qt5/tools.json` (белые списки команд и git-подкоманд).
- Тесты: `tests/unit/test_mcp_client.py`, `test_mcp_registry.py`, `test_repo_tools.py`,
  `test_repo_server.py`, `tests/fake_mcp_server.py` (stdio), `tests/fake_mcp_http.py` (remote),
  сквозные `tests/e2e/test_mcp_flow.py`, сетевой `tests/unit/test_mcp_network.py` (`network`-маркер).
- Документация: `README.md`, `AGENTS.md`, `docs/roadmap.md` (уточнение состава P3 и перенос
  автовызова в P5).

## Критерии приёмки

- `/mcp` показывает сервер документации портала и собственный сервер репозитория с их
  инструментами и делает ноль запросов к модели; `/mcp refresh` переустанавливает соединение.
- Недоступный сервер считается в стартовой сводке, печатает причину, и сессия продолжается.
- `/tool call` вызывает инструмент реального сервера портала (например, список версий документации)
  и инструмент собственного сервера (например, поиск по репозиторию).
- Собственный сервер не выходит за корень репозитория, не запускает команды вне белого списка,
  не выполняет git-подкоманды на запись и не перезаписывает существующие выгрузки.
- Автоматические тесты не обращаются к сети; реальный сервер портала проверяется отдельным
  `network`-тестом.
