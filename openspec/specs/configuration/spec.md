# configuration Specification

## Purpose
Внешняя конфигурация приложения: переменные окружения с рабочими умолчаниями, файл-шаблон
и средство изоляции состояния, которым пользуются тестовый прогон и демонстрация.

## Requirements

### Requirement: Единый префикс переменных окружения

Параметры запуска SHALL читаться из переменных окружения с единым префиксом приложения и SHALL
иметь значения по умолчанию, достаточные для запуска без настройки. Файл `.env` рядом с точкой
входа SHALL подхватываться и SHALL NOT переопределять уже заданные переменные окружения.
Каждая переменная SHALL быть описана в файле-шаблоне с её умолчанием.

#### Scenario: Запуск без настройки

- **WHEN** ни одна переменная не задана и файла `.env` нет
- **THEN** приложение запускается со значениями по умолчанию

#### Scenario: Переменная окружения важнее файла

- **WHEN** значение задано и в окружении, и в `.env`
- **THEN** используется значение из окружения

#### Scenario: Шаблон соответствует коду

- **WHEN** сверяется файл-шаблон и модуль конфигурации
- **THEN** каждая переменная из шаблона существует в конфигурации и наоборот

### Requirement: Работа без облачного ключа

Отсутствие облачного ключа SHALL NOT мешать запуску приложения. Ключ SHALL запрашиваться перед
первым облачным запросом; запрос к облачному сервису SHALL NOT отправляться без ключа. Ключ,
непригодный для передачи в HTTP-заголовок, SHALL обнаруживаться до отправки запроса.

#### Scenario: Запуск без ключа

- **WHEN** облачный ключ не задан
- **THEN** приложение запускается и сообщает, что для облачных моделей нужен ключ

#### Scenario: Облачный вопрос без ключа

- **WHEN** пользователь задаёт вопрос, требующий облачной модели, а ключа нет
- **THEN** приложение предлагает ввести ключ и не отправляет запрос без него

### Requirement: Изоляция состояния для тестов и демонстраций

Каждый файл состояния и каждый каталог данных SHALL переопределяться переменной окружения, чтобы
тестовый прогон и демонстрация SHALL NOT читать и записывать реальные файлы пользователя.

#### Scenario: Переопределение состояния

- **WHEN** переменная состояния указывает на временный путь
- **THEN** все чтения и записи этого состояния идут по указанному пути, а реальный файл
  пользователя не изменяется

#### Scenario: Полный прогон в изоляции

- **WHEN** сквозной тест запускает приложение в псевдотерминале
- **THEN** ни один файл состояния пользователя не создаётся и не изменяется
