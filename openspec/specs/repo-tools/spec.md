# repo-tools Specification

## Purpose
Собственный MCP-сервер проекта над целевым репозиторием: чтение файлов, поиск, история git,
запуск разрешённых команд сборки и сохранение выгрузки — с границами, которые нельзя обойти
ни путём, ни командой.

## Requirements

### Requirement: Состав инструментов сервера

Сервер SHALL объявлять инструменты: перечень файлов, чтение файла с номерами строк, поиск по
тексту, чтение истории git, запуск разрешённых команд сборки и сохранение выгрузки. Инструментов,
изменяющих целевой репозиторий, в этой возможности SHALL NOT быть: изменение кода появляется
вместе с конвейером задачи, где есть подтверждение и проверка.

#### Scenario: Перечень инструментов

- **WHEN** сервер объявляет свои инструменты
- **THEN** среди них есть чтение, поиск, git на чтение, разрешённые команды и выгрузка,
  и нет ни одного инструмента записи в репозиторий

#### Scenario: Чтение файла

- **WHEN** инструмент чтения получает путь и диапазон строк
- **THEN** возвращается содержимое с номерами строк, а путь указывается относительно корня

### Requirement: Границы файловых операций сервера

Любой путь, полученный инструментом, SHALL разрешаться (символические ссылки — тоже) и SHALL
лежать внутри корня целевого репозитория. Путь за пределами корня SHALL приводить к сообщению
об ошибке без выполнения операции.

#### Scenario: Путь за пределами корня

- **WHEN** инструмент получает путь с переходом вверх или абсолютный путь вне корня
- **THEN** операция отклоняется с сообщением, файл не читается

#### Scenario: Символическая ссылка наружу

- **WHEN** ссылка внутри репозитория ведёт на файл за его пределами
- **THEN** операция отклоняется так же, как при прямом выходе за корень

### Requirement: Разрешённые команды из пакета домена

Список разрешённых команд SHALL приходить из пакета домена, а не из кода сервера. Команда SHALL
запускаться без оболочки, с ограничением времени и объёма вывода. Команда вне списка SHALL
отклоняться с перечислением допустимых.

#### Scenario: Разрешённая команда

- **WHEN** запрошена команда из белого списка домена
- **THEN** она выполняется без оболочки, а результат содержит код возврата и вывод

#### Scenario: Команда вне списка

- **WHEN** запрошена команда, которой нет в белом списке
- **THEN** она не выполняется, а ответ перечисляет допустимые варианты

#### Scenario: Вывод слишком длинный

- **WHEN** команда печатает больше установленного предела
- **THEN** вывод обрезается с пометкой об обрезке, код возврата сохраняется

### Requirement: История git только на чтение

Инструмент git SHALL принимать только подкоманды чтения из белого списка домена. Подкоманда
изменения состояния репозитория SHALL отклоняться.

#### Scenario: Подкоманда чтения

- **WHEN** запрошена подкоманда чтения из белого списка
- **THEN** результат содержит её вывод

#### Scenario: Подкоманда изменения

- **WHEN** запрошена подкоманда, меняющая состояние репозитория
- **THEN** она отклоняется без выполнения

### Requirement: Выгрузка результата вне репозитория

Инструмент сохранения SHALL писать только в каталог выгрузок, вне целевого репозитория. Имя файла
SHALL быть ограничено безопасным набором символов, существующий файл SHALL NOT перезаписываться,
пустой текст SHALL отклоняться.

#### Scenario: Сохранение результата

- **WHEN** инструмент получает непустой текст и безопасное имя
- **THEN** файл появляется в каталоге выгрузок

#### Scenario: Файл уже есть

- **WHEN** файл с таким именем уже существует
- **THEN** новый файл получает отличающееся имя, прежний не изменяется

#### Scenario: Небезопасное имя или пустой текст

- **WHEN** имя содержит разделители пути или текст пуст
- **THEN** выгрузка отклоняется с сообщением

### Requirement: Отдельный процесс и ошибки как данные

Сервер SHALL работать отдельным процессом по stdio и получать корень целевого репозитория при
запуске. Ошибка инструмента SHALL возвращаться пометкой об ошибке, а не падением процесса.

#### Scenario: Ошибка инструмента

- **WHEN** инструмент получает некорректные аргументы
- **THEN** ответ помечен как ошибочный и содержит причину, сервер продолжает работу

#### Scenario: Корень не задан или не существует

- **WHEN** сервер запущен без корня или с несуществующим путём
- **THEN** приложение получает сообщение об ошибке вместо молчаливого отказа
