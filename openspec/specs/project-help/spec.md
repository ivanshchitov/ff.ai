# project-help Specification

## Purpose
Явный вход для вопросов о проекте: ответы по локальной документации и свежему MCP-контексту без изменения проекта.

## Requirements

### Requirement: Явный вопрос о проекте
Сессия SHALL поддерживать `/help [вопрос]` в TUI и web. Без вопроса команда SHALL запрашивать обзор структуры и документации проекта. Она SHALL отвечать без классификации запроса и создания задач разработки, а ответ и расход SHALL сохранять через существующий путь вопросов.

#### Scenario: Обзор
- **WHEN** пользователь вводит `/help`
- **THEN** ассистент отвечает о структуре целевого проекта по доступной документации и контексту проекта

#### Scenario: Конкретный вопрос
- **WHEN** пользователь вводит `/help` с вопросом
- **THEN** оба интерфейса показывают ответ на этот вопрос с источниками и метриками без создания задачи разработки

### Requirement: Ответ по локальной документации
Для `/help` приложение SHALL использовать существующий локальный корпус проекта, включая README и Markdown из docs, сохраняя выбранный режим отбора. Оно SHALL включать локальный поиск для запроса и восстанавливать прежние настройки после него. Отсутствующие, устаревшие и недоступные источники приложение SHALL называть явно и SHALL запрещать модели выдумывать факты о проекте без источников.

#### Scenario: Документация доступна
- **WHEN** индексированные README и docs содержат подходящие к вопросу фрагменты
- **THEN** фрагменты доставляются с исходными путями и диапазонами строк и показываются как источники ответа

#### Scenario: Источники недоступны
- **WHEN** локальный индекс отсутствует, устарел или не читается
- **THEN** ограничение называется явно, а недоступные и устаревшие фрагменты не доставляются

#### Scenario: Ошибка ответа
- **WHEN** ответ на `/help` завершается ошибкой API
- **THEN** прежние настройки локального поиска, портала и автовызова инструментов сохраняются

### Requirement: Свежий контекст проекта через MCP
Каждый `/help` SHALL получать текущий git-контекст через собственный MCP-сервер целевого проекта вызовом git status только на чтение. Вывод инструмента SHALL считаться данными. Сбой SHALL называться явно без утверждения известной текущей ветки и без молчаливой замены источника. Команда SHALL NOT вызывать инструменты записи в проект или конвейер разработки.

#### Scenario: Текущая ветка
- **WHEN** вызов MCP-сервера проекта успешен
- **THEN** свежий контекст git-ветки доставляется модели ответа и показывается в журнале запроса

#### Scenario: Detached HEAD
- **WHEN** целевой репозиторий находится в состоянии detached HEAD
- **THEN** это состояние сохраняется в доставляемом git-контексте без выдуманного имени ветки

#### Scenario: MCP недоступен
- **WHEN** вызов MCP-сервера проекта не удался
- **THEN** команда называет ограничение MCP и может отвечать только по другим доступным источникам проекта

#### Scenario: Только ответ
- **WHEN** аргумент `/help` просит изменить проект
- **THEN** команда остаётся операцией ответа и не записывает файлы и не создаёт задачу разработки
