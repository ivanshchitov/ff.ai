# AGENTS.md — контекст для агентов, работающих в репозитории ff.ai

Единый источник контекста для код-ассистентов (Claude Code, OpenCode, oh-my-pi и любых, читающих
`AGENTS.md`). `CLAUDE.md` — ссылка сюда; продуктовые детали и план — в `docs/`, контракты — в
`openspec/`.

## Что это за репозиторий

`ff.ai` — консольный (TUI) ассистент по разработке приложений под **ОС Аврора на Qt 5.6**.
Область применимости задаётся доменом: роль, границы тематики, инварианты, версии платформы
и маркеры автоопределения живут в пакете `domains/aurora-qt5/`, а не в коде. Отвечает на вопросы
по целевому репозиторию и по платформе (факты о платформе — только из документации портала
разработчиков через её MCP-сервер).

Состояние: **P0 закрыта** (ответ на вопрос, стратегии контекста, история между запусками,
отчёты, домен как данные) и **P3** (MCP-транспорты, реестр серверов, собственный сервер
репозитория), **P4** — документация портала как корпус ответа с проверяемыми ссылками.
Дальше по плану `docs/roadmap.md`: P1–P2 — корпус кода и поиск по репозиторию, P5 — автовызов
инструментов и цепочки, P6–P7 — задача, сборка и установка, P8 — память и инварианты домена,
P9–P11 — планировщик, локальная модель, web-фронтенд.

## Рабочий процесс

1. **Любое изменение поведения идёт через OpenSpec.** Одна фаза = одно изменение:
   `openspec new change <id>` → артефакты → `openspec validate <id> --strict` → реализация →
   `openspec archive <id> --yes`. Проектирование (propose) не редактирует код.
2. **Спецификация — контракт, а не план.** В спеке — наблюдаемое поведение и сценарии WHEN/THEN
   (ровно четыре решётки), в `design.md` — решения и альтернативы, в `tasks.md` — шаги.
3. **TDD.** Сначала падающий тест, затем минимальный код, затем тест слоя. Полный `pytest` —
   один раз в конце фазы, **до** архивации (архивация переписывает `openspec/specs/`).
4. **Git:** любая мутация (commit, merge, tag) — только после явного «да» пользователя; сначала
   `git status` и краткий diff. Стиль сообщений — как в истории репозитория.
5. **Релиз — это фаза плана, тег — сквозной номер релиза:** первый выпуск (P0) — `v0.1`,
   следующий закрытый выпуск (P3) — `v0.2`, и так далее. Тег не кодирует номер фазы:
   фазы идут по приоритету, а не подряд.
6. **Документация обновляется в той же фазе**, что и поведение: `README.md` и этот файл
   перепроверяются, а не только дополняются. **Полные пути конкретной машины в документах
   не пишутся** — только относительные пути и шаблоны `/path/to/...` из раздела
   «Обозначения путей».

## Правила, которые нельзя нарушить

1. **Ядро не знает домена.** В `core/` и `ui/` не должно быть ни одного идентификатора из
   `domains/*/` (имён команд платформы, модулей, маркеров). Есть тест-сторож.
2. **Домен — данные.** Новая область применимости = новый пакет `domains/<id>/`, а не правки ядра.
3. **В целевой репозиторий не пишется ничего лишнего** — ни индекс, ни состояние, ни `.gitignore`.
4. **Пути состояния — ленивые.** Раскладка задаётся переменными `FFAI_*` и читается при
   обращении, а не при импорте: значения по умолчанию с `config.X` в сигнатурах «замерзают».
5. **Никаких секретов и ключей** в коде, выводе, логах и патчах; материал подписи не печатается.
6. **Деструктивные git-операции запрещены** (`--force`, `reset --hard`, `clean -f`, `branch -D`).
7. **Состав SDK, целей и тулинга не меняется** — это ручная работа пользователя.
8. **Тесты не «чинятся» отключением** (`skip`, `xfail`, `--no-verify`).
9. **Платформенный факт приводится со ссылкой** на документацию портала и с указанием версии;
   по памяти о платформе не отвечают.
10. **Одна операция за раз.** Сессия сериализует операции мьютексом; интерфейсы подписываются
    на события и рендерят снимки, не читая внутренности агента.

## Обозначения путей

Полные пути конкретной машины в документации не используются — только относительные пути и
шаблоны одного вида, `/path/to/...`:

| Шаблон | Что это |
|---|---|
| `/path/to/ff.ai` | каталог установки инструмента (клон репозитория ff.ai) |
| `/path/to/aurora-project` | целевой репозиторий приложения под Аврору |
| `/path/to/AuroraOS` | установка Аврора SDK; `sfdk` — в `/path/to/AuroraOS/bin` (по умолчанию `$HOME/AuroraOS`) |
| `/path/to/AuroraPlatformSDK` | установка Аврора Platform SDK (по умолчанию `$HOME/AuroraPlatformSDK`) |
| `/path/to/auroraos-regular-keys` | материал подписи (по умолчанию `$HOME/.auroraos-regular-keys`) |
| `/path/to/ssh/config` | конфигурация SSH пользователя (по умолчанию `$HOME/.ssh/config`) |
| `/path/to/data/ff-ai` | каталог данных приложения (по умолчанию `$XDG_DATA_HOME/ff-ai`) |
| `/path/to/cache/ff-ai/path-hash` | каталог кэша; `path-hash` — подкаталог с хешем пути целевого репозитория (по умолчанию `$XDG_CACHE_HOME/ff-ai`) |

Сегмент `path-hash` и имя проекта в шаблоне — условные подстановки, а не реальные каталоги.

## Домен: где истина

- **Платформа:** MCP-сервер `dev-aurora`, `https://developer.auroraos.ru/api/mcp`, транспорт remote
  (streamable HTTP), токен не нужен. Инструменты: `search`, `get_document`, `get_doc_versions`,
  `search_code`, `get_code_source`, `get_ext_tools_list`, `get_portal_info`, `echo`.
  Прямой `GET` адреса отвечает `403` — это признак MCP-эндпоинта; соединение проверяется вызовом
  `echo`. В приложении он подключается по записи пакета `domains/aurora-qt5/servers.json`
  (транспорт `http`, без токена), проверка соединения — вызовом объявленного инструмента.
- **Версии:** документация портала по умолчанию — 5.2.1 (флаг `latest` стоит у неё, а не у самой
  старшей 5.2.2). Локально установлен Аврора SDK **5.1.5.105-mb2** в `/path/to/AuroraOS`
  (по умолчанию `$HOME/AuroraOS`), `sfdk` — в `/path/to/AuroraOS/bin`, не в PATH. Рассинхрон
  версий проговаривается в ответе.
- **Цели сборки:** `AuroraOS-5.1.5.105-MB2-{aarch64,armv7hl,x86_64}` — `aarch64`/`armv7hl`
  устройства, `x86_64` эмулятор; снимки `.default` отбрасываются. Platform SDK на машине нет.
- **Ключевые регламенты:** `reference/public_api` (допустимые модули и зависимости, QtWidgets
  запрещён, разрешения), `guidelines/rpm_requirements/spec_requirements` (`.spec`),
  `guidelines/rpm_requirements/desktop_requirements` (`.desktop`, `[X-Application]`, `Permissions`),
  `sdk/tools/{rpmsign_external,rpm_validator,mb2}`, `sdk/psdk/build`.

## Грабли, проверенные на практике

- **API пакета `mcp` 2.3 — snake_case.** У моделей `input_schema` и `is_error` (на проводе
  `inputSchema`/`isError`, но библиотека переводит поля сама), сервер собирается как
  `from mcp.server.mcpserver import MCPServer` (бывший FastMCP), `log_level` — литерал в верхнем
  регистре. Ошибку инструмента надо поднимать как `ToolError` (из `mcp.server.mcpserver.exceptions`):
  обычное исключение клиент видит как «Error executing tool …» **без причины**, а на stderr
  сервера печатается traceback. Описания параметров живут в докстроке инструмента — в схему
  аргументов они не попадают, поэтому `Args:` обязателен и для модели, и для отчёта `/tool`.
- **Сервер портала отвечает `403` на попытку завершить сессию.** Подключение к этому моменту уже
  отработало: это особенность сервера, а не сбой, и в отчёт как ошибка не идёт.
- **Обход реестра MCP в тестах всегда идёт на локальную заглушку** (`tests/conftest.py` и
  `tests/e2e/harness.AppSession` ставят `FFAI_MCP_COMMAND`/`FFAI_MCP_ARGS`), иначе любой прогон
  поднимал бы сервер портала и ходил в сеть. Живой реестр включается явно: `mcp_command=""`
  в `AppSession` или снятые переменные. Тесты, проверяющие настоящий реестр, должны снимать
  эти переменные сами.
- **Собственный сервер не пишет в целевой репозиторий.** Патчи появятся вместе с конвейером
  задачи (P6), где есть подтверждение и прогон проверок; выгрузка идёт в каталог выгрузок,
  а не в репозиторий.
- **Поиск по документации — одна сессия соединения на один поиск** (`MCPClient.session()`):
  одноразовый вызов поднимает серверный процесс заново, и пять инструментов стоили бы
  двадцать секунд на вопрос вместо трёх.
- **Проверка ссылок работает только для свободного формата.** У JSON, компактного и диффа свои
  контракты: обязательные блоки цитат им противоречили бы, источники им печатает приложение.
- **Единственная форма ответа без ссылки — явный отказ**: ответ, начинающийся словами
  «Документация не относится к вопросу», принимается без цитаты. Это нужно домену: смежные
  вопросы (уровень 3) разрешены, а проверка иначе заменяла бы полезный ответ отказом.
- **Вторая ступень отбора — вспомогательный запрос, а не часть поиска.** Кандидатов оценивает
  модель сессии (`reranking`), а решение об отборе принимает приложение: оценка — данные для
  порога, а не приговор. Негодный ответ оценщика (пропуск, чужой идентификатор, оценка вне
  диапазона, не JSON) останавливает доставку с состоянием `rerank_failed` — доставлять сырые
  кандидаты в этом случае значит вернуть шум и при этом выглядеть так, будто отбор состоялся.
- **Реранкинг не восстанавливает пропущенное поиском.** Если первый этап не вернул нужный документ,
  вторая ступень может лишь переупорядочить то, что есть; в контрольном прогоне вопрос про `moc`
  так и остался без документа по архитектуре Qt.
- **Портал разработчиков ограничивает частые автоматические обращения.** Несколько сетевых прогонов
  подряд дают быстрый отказ «Server returned an error response», хотя одиночный запрос в тот же
  момент работает. Это не сбой клиента: повторите прогон позже.
- **Список файлов корпуса берётся у git, а не у своего разбора `.gitignore`.** В репозитории
  работает `git ls-files --cached --others --exclude-standard`: он сам учитывает игнорирование и
  не спускается в каталоги сборки; вне git — обычный обход, и отчёт называет способ. Свой разбор
  `.gitignore` (вложенные файлы, отрицания, шаблоны каталогов) — источник тихих расхождений.
- **Индекс заменяется атомарно.** Сборка идёт во временный файл рядом и делает `os.replace` после
  успешной записи: иначе обрыв на середине (нет места, нет прав, исключение в разборе) оставил бы
  пользователя с полупустым индексом и без прежнего, а прежний ещё пригоден.
- **Правила корпуса — данные домена, ядро не знает расширений.** Расширения исходников, исключения,
  предел размера и признаки начала блока живут в `domains/<id>/corpus.json`; тест «в `core/` и `ui/`
  нет идентификаторов домена» это проверяет. Файлы без признаков структуры разбиваются окнами —
  это честнее, чем делать вид, что структура найдена.
- **Корпус кода называется `/code`, а не `/docs`.** `/docs` занята документацией портала (режим,
  версия, трассировка, отбор, порог) и описана в README и e2e: второй корпус на том же префиксе
  сломал бы существующее поведение.
- **Демонстрационный репозиторий в e2e обязан быть git-репозиторием.** Приложение отказывается
  работать вне git-корня, поэтому тест корпуса делает `git init` в своём временном каталоге.
- **Маршрутизация памяти — правила домена, а не модель.** Второй извлекатель стоил бы запроса на
  каждую реплику, был бы недетерминированным и непроверяемым; правила видны в `/memory`, и
  пользователь понимает, почему запись появилась. Правила держим узкими: широкий образец вроде
  `без \w+` затягивал бы в память обычные вопросы.
- **Источник записей — только реплики пользователя.** Ответ модели в память не попадает: иначе
  ассистент запоминал бы свои догадки и потом отвечал по ним как по фактам пользователя.
- **`/clear` чистит диалог, но не рабочую память задачи.** Цель и ограничения текущей задачи — не
  разговор: они остаются вместе с долговременной памятью, у которой своё хранилище. Так это
  зафиксировано спекой фазы, хотя донор чистил и рабочую память.
- **Правила домена идут в каждый запрос, а проверка идёт по коду.** Промпт снижает вероятность
  нарушения, код ловит случившееся: подстрока запрещённого стема, окно отрицания (20 символов),
  отказ не проверяется, нарушение стоит одного повтора и замены ответа. Отклонённый ответ в историю
  не попадает — иначе он стал бы примером для следующего запроса.
- **Аргументы инструментов проверяются до запуска процесса.** Секрет в аргументе не должен дойти ни
  до сервера, ни до журнала вызовов: отказ до действия — тот же принцип, что у запрещённых команд
  конвейера.
- **Инструмент SDK называется доменом, а не ядром.** Путь, шаблоны команд, образец цели и
  запрещённые команды лежат в `domains/<id>/ops.json`; ядро подставляет значения и не знает имён
  команд. Цели читаются из вывода самого инструмента: свой список устарел бы молча.
- **Запреты конвейера сверяются с подкомандой, а не со всем argv.** Путь к `sfdk` — свойство машины
  (путь к SDK — свойство машины), и сравнение с ним запрета не имеет смысла; запрет — префикс подкоманды
  (`tools install`, `maintain`), причём чтение (`tools list`) разрешено.
- **Сборка идёт в `build_<arch>/`.** Живой прогон P6 показал, чем это важно: `qmake`/`make` в корне
  проекта оставляют `Makefile`, `.qmake.stash` и каталог приложения.
- **Подстановка в шаблонах команд — своя, не `str.format`.** В командах встречаются фигурные скобки
  самого инструмента (`--qf %{SIGPGP:pgpsig}`), и формат строки принял бы их за свои поля.
- **Подпись проверяется по строкам вывода, а не по коду возврата.** `rpm` успешно отвечает и на
  пакет без подписи. Признаки «подписано»/«без подписи» — данные домена, и они подобраны так, чтобы
  «пакет без подписи» не считался подтверждением.
- **Единственная запись в чужой проект — подтверждённый патч задачи.** Патч проверяется правилами
  домена до показа пользователю и применяется `git apply` только после явного «да»; отклонённый
  патч остаётся в снимке задачи с причиной, а не выбрасывается. Своего применения diff-ов нет:
  `git apply --check` знает про контекст больше, чем построчный разбор, а ошибка в нём оставила бы
  файл половинчатым.
- **Сначала код, потом модель.** Запрещённые конструкции домена, обязательные элементы `.spec`,
  границы путей и чистота применения проверяются кодом **до** модельного ревью: модель,
  проверяющая свой же патч, подтверждает свои же ошибки. Ревью добавляет замечания и не отменяет
  детерминированный вердикт.
- **Недоступная проверка называется, а не считается пройденной.** Проверка сборки идёт через
  инструмент сервера репозитория (своего раннера команд приложение не заводит), а её отсутствие —
  отдельное состояние `BuildUnavailable`: «не проверялось» нельзя показывать ни как успех, ни как
  провал.
- **Сборка запускается на этапе проверки, а не после каждого патча.** Сборка дороже всех остальных
  проверок вместе; на этапе выполнения проверяются содержимое и применение.
- **Одна операция конвейера — один вызов и одна запись состояния.** Поэтому пауза безопасна:
  останавливаться можно между операциями, а перезапуск продолжает с сохранённого шага. Прерывание
  во время прогона означает паузу, а не выход (в cbreak `ISIG` остаётся, и Ctrl+C приходит внутрь
  цикла); общее правило «Ctrl+C выходит» продолжает действовать вне прогона.
- **Журнал переходов ведёт и отказы.** Попытка перехода — часть истории задачи: отказ видно в
  `/task` рядом с принятыми переходами.
- **Отклонённый патч не зацикливает конвейер.** Номер следующей подзадачи считается по факту
  попытки, а не по факту успеха; исправление снимает записи об отклонённых патчах и даёт свежую
  попытку, но не трогает применённые — готовое не переделывается.
- **Строки панели прогона экранируются** (`rich.markup.escape`): план и замечания — текст модели.
- **Сквозные тесты задачи замедляют ответы заглушки** (`Reply.delay`): с мгновенными ответами
  прогон заканчивается быстрее, чем тест успевает подтвердить патч, и проверка становится гонкой.
- **Автовызов стоит одного запроса выбора на раунд, а не на шаг.** Цепочка шагов приходит одним
  ответом, продолжение — только по явной пометке `more`: иначе разговор об инструментах удвоил бы
  цену каждого вопроса. Флоу в один раунд завершается сам, и 30 сквозных тестов, считающих запросы,
  ожидают именно одного запроса выбора.
- **Данные между шагами передаются ссылкой `$N`, а не пересказом.** Значение аргумента, целиком
  равное `$N`, заменяется полным текстом результата (или отдельной строкой многострочного значения —
  так собирается выгрузка); `$N` внутри строки с другим текстом остаётся как есть. Шаги нумеруются
  глобально по всем раундам, и объёмы передачи видно в журнальной строке шага.
- **Маршрут шага — код, а не слово модели.** Сервер берётся по снимкам подключений: названный, если
  он объявил инструмент; иначе единственный объявивший (с пометкой перенаправления); при отсутствии
  или неоднозначности шаг падает без запуска процесса.
- **Каталог инструментов — из снимков, имена в ядре не живут.** Тест «в `core/` и `ui/` нет
  идентификаторов домена» это покрывает вместе с проверкой, что имён инструментов в ядре нет.
- **Результаты инструментов — служебное сообщение, не история.** Они входят в запрос отдельным
  system-сообщением выше реплик диалога и не попадают ни в `history.json`, ни в память.
- **Собственный сервер репозитория обязан получить `FFAI_EXPORTS_DIR` в `env_keys`.** Каталог
  выгрузок читает серверный процесс, а не приложение: без переменной выгрузка ушла бы в каталог
  состояния по умолчанию вместо того, что просит запуск. Живой прогон это и показал — отчёт оказался
  в домашнем каталоге.
- **Переопределение реестра умеет несколько серверов.** `FFAI_MCP_ARGS` с разделителем « | » даёт
  по серверу на набор аргументов: сквозная проверка маршрутизации поднимает две заглушки.
- **В сквозном слое автовызов выключен по умолчанию.** `tests/e2e/harness.AppSession` передаёт
  `FFAI_AUTO_TOOLS=0`, а тесты автовызова включают его явно: иначе каждый тест, считающий запросы или
  читающий первый запрос, мерил бы запрос выбора вместо ответа.
- **Поиск по коду ранжирует векторами, но токенный путь остаётся.** Векторы считает локальный
  embedding-пресет при сборке индекса; векторы принадлежат модели, и чужие не используются никогда —
  смешать их значит получить бессмысленную близость, которую по результатам не заметить. При готовых
  векторах `enhanced` не делает запрос-переформулировку (это и была цена слабости токенного поиска);
  нет сервера или векторов — причина называется в `/code trace`, поиск идёт токенами.
- **Схема индекса версионируется.** Версия 2 добавила таблицу векторов: индекс прошлой версии не
  читается как пригодный — нужна пересборка `/code index`, и это объявляется, а не подразумевается.
- **Вторая ступень отбора общая для корпусов.** `core/reranking.py` (бывший `docs_reranking`)
  принимает имя ассета-инструкции параметром: у документации своя формулировка, у кода своя, а
  разбор ответа, отбор по порогу и снимок оценок — одни и те же. Поведение документации при этом
  не меняется, и это проверяют её собственные тесты.
- **Цитата кода подтверждается либо диапазоном, либо одним путём файла.** Модель регулярно пишет
  `src/models.cpp` без `:L10-L40`; требовать префикс `L` значило бы ловить формат записи, а не
  наличие ссылки. При этом цитата обязана быть дословной: минимум для кода (40 символов после
  нормализации) выше, чем для документации, а фрагмент короче минимума подтверждается цитатой
  целиком — иначе короткий QML-файл нельзя подтвердить никогда, и ответ по нему гарантированно
  заменялся бы текстом «не знаю» (живой прогон это и показал).
- **Новая переменная окружения обязана попасть в `.env.example`.** Тест
  `test_template_and_code_agree_about_variables` сверяет множество имён из шаблона с множеством
  имён, которые читает код: шаблон — единственное описание настроек, и устареть он не имеет права.
- **Сквозной тест, задающий вопрос, не должен оставлять корпус документации включённым.** Реестр
  MCP заменяется фейковым сервером по умолчанию: если передать пустые `mcp_command`/`mcp_args`,
  домен найдёт свой настоящий сервер портала, и тест уйдёт в сеть (поймано на живом фрагменте
  документации в запросе кода).
- **Кэш версий документации живёт на объекте ретривера**, `/docs version` сбрасывает его.
  Версия документации может быть новее установленного SDK — рассинхрон проговаривается в блоке
  фрагментов, а не в промпте домена: промпт знает правило, числа приносит снимок поиска.

- **Значения по умолчанию из конфигурации должны быть ленивыми.** `def f(path=config.HISTORY_FILE)`
  запоминает путь при импорте и игнорирует переменные окружения: путь берётся в момент вызова
  (`path or config.HISTORY_FILE`). Тест на это уже есть.
- **Ожидание на экране не должно опираться на маркер, который уже есть в скроллбэке.**
  `AppSession.ask()` считает строки метрик до отправки и ждёт их роста — иначе второй вопрос
  «завершается» мгновенно по строке `⏱` первого ответа.
- **Каталог состояния создаётся при первой записи** (`HistoryManager.save()`), а сбой записи
  не отменяет ответ — причина остаётся в `last_error` и показывается строкой журнала.
- **Новый файл состояния = новая переменная `FFAI_*` и проброс в `tests/conftest.py` и
  `tests/e2e/harness.AppSession`.** Без обоих тест читает и пишет реальные файлы пользователя.
- **Тесты терминала** — pty + `pyte`; ждать отрисованный маркер, а не «тишину»: `rich.Live`
  перерисовывается постоянно. Байты, отправленные до отрисовки панели, достанутся её циклу чтения.
- **`openspec archive` без `--yes`** блокируется на подтверждении; `validate --strict` — до показа
  плана и перед архивацией; `## Purpose` в дельте допустим только для новой возможности,
  а `MODIFIED` не должен терять существующие сценарии.
- **Сборка на macOS:** `%defattr` в `%files` обязателен, иначе ошибка валидации.
- **Подпись пакета** запрашивает кодовую фразу интерактивно — в конвейере она передаётся
  `KEY_PASSPHRASE`. Проверка подписи — по строкам вывода `rpmsign-external dump`, а не по коду
  возврата: `dump` завершается нулём и для неподписанного пакета.
- **`rpm -q`** отвечает «не установлен» и для приложения, поставленного через APM: проверять надо
  `ru.omp.APM.GetPackage`.
- **Недоступность SDK или устройства** — это сообщение с причиной и кодом выхода, а не падение
  прогона; ничего не подменяется молча.

## Команды

```bash
.venv/bin/python -m pytest -q                              # всё: юниты и сквозной прогон
.venv/bin/python -m pytest tests/unit -q                   # быстрый слой
.venv/bin/python -m pytest tests/e2e -q                    # приложение в псевдотерминале
.venv/bin/python -m pytest -s --show-tui=live tests/e2e/…  # видеть экран приложения
openspec validate --all --strict                           # проверка спецификаций
```

Прогон приложения: `cd /path/to/aurora-project && /path/to/ff.ai/ff-ai.py` (флаги `--repo`,
`--domain`). Состояние изолируется переменными `FFAI_*` — см. `.env.example`.

Команды слоёв донора (перенесены без изменений): `/commands`, `/settings`, `/models`, `/branches`,
`/context`, `/usage`, `/domain`, `/exit`; их поведение описано спецификациями `answer-formats`,
`settings-screen`, `model-selection`, `context-strategies`, `history-persistence`,
`usage-accounting`, `terminal-ui`, `test-infrastructure`.
Расписание: `/schedule` — снимок заданий и прогонов; задания выполняет `ff-ai-scheduler.py`
(`--once` для одного прохода), а приложение объявляет о новых прогонах после ответа.
Локальная модель: пресеты из `llama_server/models.ini`; автозапуск выключается `FFAI_LLAMA_AUTOSTART=0`
(в тестах он выключен всегда), локальному пресету не нужен облачный ключ.
Web-режим: `--web` поднимает тот же фасад в браузере; в этом режиме локальный сервер модели не
поднимается, а обход реестра MCP при старте не делается.
Память, профиль и правила: `/memory` (отчёт; `goal`, `remember`, `forget`), `/profile` (отчёт;
`setup`, `use`, `forget`), `/invariants` (таблица правил и последняя проверка).
Конвейер операций: `/ops` — состояние SDK, цели, шаги; `/ops target <архитектура>`,
`/ops build|sign|verify|install|run`. Путь к SDK приходит переменной, **названной в правилах домена**
(`ops.json` → `tool.env`, по умолчанию `FFAI_SFDK`), поэтому в `.env.example` этих имён нет: шаблон
сравнивается тестом с тем, что читает код, а имя переменной — данные домена. Кодовая фраза подписи —
тем же способом (`signature.key_env`, по умолчанию `FFAI_SIGN_KEY`).
Задача: `/task` — отчёт о задаче и очереди, `/task add <цель>`, `/task run` (прогон под панелью),
`/task stage <этап>` — через тот же шлюз переходов, `/task stop` — очередь. Пауза в прогоне —
клавиша `p` или Ctrl+C; состояние задачи в `FFAI_TASK_FILE`, отчёты в `FFAI_TASKS_DIR`.
Автовызов инструментов: `/tool auto on|off` (по умолчанию включён), `/tool flow` — отчёт о
последнем флоу; `FFAI_AUTO_TOOLS=0` выключает автовызов, и тогда вопрос не сопровождается выбором.
Команды корпуса кода: `/code index [fixed|structural]`, `/code status`, `/code compare`,
`/code retrieval baseline|enhanced`, `/code threshold <0..1>`, `/code tune before=<n> after=<n>`,
`/code mode on|off`, `/code trace` —
отчёты без обращений к модели; индекс лёг бы в `FFAI_INDEX_FILE`, по умолчанию в кэш состояния по
хешу пути репозитория.
Команды корпуса документации: `/docs` (отчёт о последнем поиске), `/docs mode on|off`,
`/docs version <версия>`, `/docs trace`, `/docs retrieval baseline|enhanced`, `/docs threshold <0..1>`. Команды MCP: `/mcp` (серверы, протоколы, инструменты),
`/mcp refresh`, `/tool`
(перечень инструментов с параметрами), `/tool call <инструмент> ключ=значение …` — значение
с пробелами берётся в кавычки: `/tool call repo_search query="как собрать пакет"`.
