# AGENTS.md — контекст для агентов, работающих в репозитории ff.ai

Единый источник контекста для код-ассистентов (Claude Code, OpenCode, oh-my-pi и любых, читающих
`AGENTS.md`). Продуктовые детали — в `docs/`, план — в `docs/roadmap.md`, контракты — в
`openspec/`.

## Что это за репозиторий

`ff.ai` — консольный (TUI) агент-ассистент по разработке с тонким локальным web-фронтендом.
Область применимости задаётся доменом: первый домен — **разработка приложений под ОС Аврора
на Qt 5.6**. Ассистент отвечает по коду целевого репозитория с цитатами `path:L10-L40`, по
платформе — только по документации портала разработчиков через её MCP-сервер, выполняет задачи
по изменению кода и проводит их через сборку, подпись и установку.

**Статус: планирование.** Кода ещё нет — только документация и OpenSpec. Первая фаза (P0) не начата.
Не ищите `core/`, `ui/`, `tests/` — их пока не существует; они появятся по `docs/roadmap.md`.

## Рабочий процесс

1. **Любое изменение поведения идёт через OpenSpec.** Одна фаза = одно изменение:
   `openspec new change <id>` → артефакты → `openspec validate <id> --strict` → реализация →
   `openspec archive <id> --yes`. Проектирование (propose) не редактирует код.
2. **Спецификация — это контракт, а не план.** В спеке — наблюдаемое поведение и сценарии
   WHEN/THEN; в `design.md` — решения и альтернативы; в `tasks.md` — шаги. Сценарии строго
   с четырьмя решётками.
3. **TDD.** Сначала падающий тест, затем минимальный код, затем тест слоя. Полный `pytest` —
   один раз в конце фазы, **до** архивации (архивация переписывает `openspec/specs/`).
4. **Git:** любая мутация (commit, merge, tag) — только после явного «да» пользователя;
   сначала `git status` и краткий diff. Стиль сообщений — как в истории репозитория.
5. **Документация обновляется в той же фазе**, что и поведение: `README.md` и этот файл
   перепроверяются, а не только дополняются. **Полные пути конкретной машины в документах
   не пишутся** — только относительные пути и шаблоны `/path/to/...` из раздела
   «Обозначения путей».

## Правила, которые нельзя нарушить

Это продуктовые инварианты ff.ai — они же критерии ревью любого изменения.

1. **Ядро не знает домена.** В `core/` и `ui/` не должно быть ни одного идентификатора из
   `domains/*/` (имён команд платформы, модулей, путей документации). Есть тест-инвариант.
2. **Домен — данные.** Новая область применимости = новый пакет `domains/<id>/`, а не правки ядра.
3. **В целевой репозиторий не пишется ничего лишнего** — кроме изменений, которые попросил
   пользователь. Индекс и состояние живут вне репозитория.
4. **`.gitignore` и чужие файлы не переписываются.** Состояние инструмента — в `.aurora/`,
   исключение — строкой в `.git/info/exclude`.
5. **Никаких секретов и ключей** в коде, выводе, логах и патчах; материал подписи лежит
   в `/path/to/auroraos-regular-keys`, его содержимое не печатается никогда.
6. **Деструктивные git-операции запрещены** (`--force`, `reset --hard`, `clean -f`, `branch -D`).
7. **Состав SDK, целей и тулинга не меняется:** `sfdk maintain`, `SDKMaintenanceTool`,
   `sfdk tools install|update|remove|create`, `sdk-assistant target create|remove|update` —
   отклоняются до выполнения.
8. **Тесты не «чинятся» отключением** (`skip`, `xfail`, `--no-verify`).
9. **Платформенный факт приводится со ссылкой** на документацию портала; без ссылки утверждение
   не принимается, а по памяти о платформе не отвечают вообще.
10. **Одна операция за раз.** Сессия сериализует операции мьютексом; фронтенды только подписываются
    на события и рендерят снимки, не читая внутренности агента.

## Обозначения путей

Полные пути конкретной машины в документации не используются — только относительные пути и
шаблоны одного вида, `/path/to/...`:

| Шаблон | Что это |
|---|---|
| `/path/to/ff.ai` | каталог установки инструмента (клон репозитория ff.ai) |
| `/path/to/aurora-project` | целевой репозиторий приложения под Аврору, с которым работает ассистент |
| `/path/to/AuroraOS` | установка Аврора SDK; `sfdk` — в `/path/to/AuroraOS/bin` (по умолчанию `$HOME/AuroraOS`) |
| `/path/to/AuroraPlatformSDK` | установка Аврора Platform SDK (по умолчанию `$HOME/AuroraPlatformSDK`) |
| `/path/to/auroraos-regular-keys` | материал подписи (по умолчанию `$HOME/.auroraos-regular-keys`) |
| `/path/to/ssh/config` | конфигурация SSH пользователя (по умолчанию `$HOME/.ssh/config`) |
| `/path/to/data/ff-ai` | каталог данных приложения: история, память, профиль, задачи, расписание, выгрузки (по умолчанию `$XDG_DATA_HOME/ff-ai`) |
| `/path/to/cache/ff-ai/path-hash` | каталог кэша; `path-hash` — подкаталог с хешем пути целевого репозитория (по умолчанию `$XDG_CACHE_HOME/ff-ai`) |

Сегмент `path-hash` и имя проекта в шаблоне — условные подстановки, а не реальные каталоги.

## Домен: где истина

- **Платформа:** MCP-сервер `dev-aurora`, `https://developer.auroraos.ru/api/mcp`, транспорт remote
  (streamable HTTP), токен не нужен. Инструменты: `search`, `get_document`, `get_doc_versions`,
  `search_code`, `get_code_source`, `get_ext_tools_list`, `get_portal_info`, `echo`.
  Прямой `GET` этого адреса отвечает `403` — это не поломка, а признак MCP-эндпоинта; соединение
  проверяется вызовом `echo`.
- **Версии:** документация по умолчанию — 5.2.1 (флаг `latest` стоит у неё, а не у самой старшей
  5.2.2). Локально установлен Аврора SDK **5.1.5.105-mb2** в `/path/to/AuroraOS` (по умолчанию
  `$HOME/AuroraOS`), `sfdk` — в `/path/to/AuroraOS/bin`, не в PATH. Рассинхрон версий проговаривается
  в ответе.
- **Цели:** `AuroraOS-5.1.5.105-MB2-{aarch64,armv7hl,x86_64}` — `aarch64`/`armv7hl` устройства,
  `x86_64` эмулятор; снимки `.default` отбрасываются. Platform SDK на машине нет.
- **Ключевые регламенты:** `reference/public_api` (допустимые модули и зависимости, QtWidgets
  запрещён, разрешения), `guidelines/rpm_requirements/spec_requirements` (`.spec`),
  `guidelines/rpm_requirements/desktop_requirements` (`.desktop`, `[X-Application]`, `Permissions`),
  `sdk/tools/{rpmsign_external,rpm_validator,mb2}`, `sdk/psdk/build`.

## Грабли, проверенные на практике

- **Новый файл состояния = новая переменная `FFAI_*` и проброс в `tests/e2e/harness.AppSession`.**
  Без обоих тест читает и пишет реальные файлы пользователя.
- **Тесты терминала** — pty + `pyte`; ждать отрисованный маркер, а не «тишину»: `rich.Live`
  перерисовывается постоянно. Байты, отправленные до отрисовки панели, достанутся её циклу чтения.
- **`openspec archive` без `--yes`** блокируется на подтверждении; `validate --strict` — до показа
  плана и перед архивацией; `## Purpose` в дельте допустим только для новой возможности,
  а `MODIFIED` не должен терять существующие сценарии.
- **Подпись пакета** запрашивает кодовую фразу интерактивно — в конвейере она передаётся
  `KEY_PASSPHRASE`. Проверка подписи — по строкам вывода `rpmsign-external dump`, а не по коду
  возврата: `dump` завершается нулём и для неподписанного пакета. `verify` требует корневой CA
  и не используется.
- **Сборка на macOS:** `%defattr` в `%files` обязателен, иначе ошибка валидации.
- **Валидатор RPM** вызывается автоматически при установке, и пакет без валидации не установится;
  отдельный прогон в среде сборки показывает причину заранее.
- **`rpm -q`** отвечает «не установлен» и для приложения, поставленного через APM: проверять
  надо `ru.omp.APM.GetPackage`.
- **При нескольких `.spec`** среда сборки не выбирает файл сама и падает с «Multiple spec files
  found — please select one».
- **Недоступность SDK или устройства** — это сообщение с причиной и кодом выхода, а не падение
  прогона; ничего не подменяется молча.
