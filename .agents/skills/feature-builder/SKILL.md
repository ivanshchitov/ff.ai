# Разработка фичи ff.ai

Этот процесс работает с любой моделью: названия сторонних навыков не являются зависимостью.
Сначала прочитать `AGENTS.md`, действующие спецификации и относящийся к задаче план.

1. Проверить `git status`, текущую ветку и активные OpenSpec-изменения. Сохранить чужие правки.
   Работать в отдельной ветке; не создавать вторую, если пользователь уже выбрал рабочую ветку.
2. Для поведения создать одно OpenSpec-изменение: proposal, design, дельта-спеки, tasks.
   Для требования использовать наблюдаемое поведение и `#### Scenario:` с WHEN/THEN.
   Запустить `openspec validate <id> --strict`. Существующий план детализировать в tasks.md,
   не писать конкурирующий план и не повторять уже полученное согласие на реализацию.
3. Каждый шаг выполнять через TDD: тест на отсутствующее поведение, подтверждённое падение,
   минимальный код, проверка затронутого слоя. Причину неожиданного падения исследовать до исправления.
   Для текста и shell-сценариев проверять содержание и синтаксис, не создавать тесты на строки текста.
4. Обновить README, AGENTS.md и документацию в том же изменении; перепроверить старые утверждения.
   Новые FFAI-пути добавить в `.env.example` и изоляцию unit/e2e. Состояние хранить вне целевого проекта.
5. До закрытия выполнить полный локальный набор:
   `.venv/bin/python -m pytest -m 'not network' -q`.
   Обычный `pytest` исключает slow; `-m ""` включает network. Живые проверки включать отдельно.
6. Перед архивацией проверить изменение и все спеки; затем `openspec archive <id> --yes`.
   После архивации проверить `openspec validate --all --strict`; код не менялся — тесты не повторять.
7. Перед коммитом показать status и краткий diff. Следовать уже разрешённой пользователем
   последовательности коммитов; если разрешения нет — спросить. Merge, tag, push и публикация
   требуют собственной авторизации; разрешение коммитов их не включает.

При ограничении среды сообщить точную причину и невыполненную проверку; не заменять её заявлением об успехе.
Пути в сохраняемых документах — относительные и `/path/to/...`; личные абсолютные пути не писать.
Версия релиза определяется существующими тегами ff.ai, а не номером задачи челленджа.
