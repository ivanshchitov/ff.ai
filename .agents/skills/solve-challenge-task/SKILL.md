# Задача челленджа: ff.ai, код и видео

Прочитать `AGENTS.md` и `../feature-builder/SKILL.md`; выполнить описанный там процесс
даже если модель не умеет вызывать инструмент Skill. Проект челленджа читать;
черновик сдачи создавать в ff.ai, его README пользователь обновляет отдельно.

## Разбор

- Зафиксировать день, исходный текст, дословные критерии результата и формат сдачи.
- Подготовить небольшой план и сценарий демо, где виден каждый критерий.
- Если день уже сдан, уточнить новую цель; сдачу не перезаписывать.
- Сохранить принятые решения и разрешения. Запрос на реализацию плана и коммиты разрешает
  именно эти действия; повторное согласие не запрашивать. Публикация остаётся отдельным действием.

## Реализация

Выполнить feature-builder. Демо снимать с проверенного кода.
День челленджа не задаёт номер релиза: прочитать теги ff.ai и предложить следующий сквозной номер.
Установку/изменение SDK и доступов не выполнять автоматически.

## Запись

Скрипт: `scripts/record_screen.sh` относительно каталога этого навыка.
Перед записью — `doctor` и сухой прогон. Во время подготовки-only этот навык не записывает экран.

1. Создать временный каталог демо. В отдельном процессе задать FFAI_STATE_DIR и FFAI_CACHE_DIR;
   переопределить history, memory, profile, task, schedule, tasks, exports, index и другие явные
   пути FFAI, чтобы они не ссылались на реальные пользовательские данные.
   Не перемещать, не очищать и не восстанавливать пользовательские файлы; каталог удалить
   только после завершения собственного демо-процесса и рекордера.
2. Запускать `/path/to/ff.ai/ff-ai.py --repo /path/to/aurora-project --domain aurora-qt5`.
   Секреты вводить локально без эха; .env, ключи и чужие окна не показывать.
3. Сценарий автоматизировать: ожидать новый отрисованный результат/метрики, не эхо ввода
   и не произвольную паузу. Созданное окно адресовать по id; чужие окна не менять.
4. Запустить запись в `videos/dayMM-demo`; остановить рекордер в finally и по лимиту.
   Проверить длительность 30–600 секунд, отсутствие чёрного кадра и прочитать ключевые кадры.
5. Если запись недоступна, сообщить причину и передать пользователю ручной шаг.
   Вывод терминала, слайды и скриншоты не выдавать за запись экрана.

## Материалы

В игнорируемом `videos/` подготовить `dayMM-README-draft.md` и `dayMM-release-notes.md`.
Название решения — ff.ai. Ссылку на код строить по origin ff.ai и фактическому тегу;
ссылка на релиз имеет вид `<repository-url>/releases/tag/<tag>`.
URL видео указывать только после реальной загрузки пользователем: не придумывать
GitHub assets или другие опубликованные адреса. Все метрики брать из свежих результатов.

Передать пути к записи и черновикам, статус кода и ручные шаги публикации.
«Сдано» допустимо только когда действительно доступны обе части: код и видео.
